A refund agent, broken 32 ways

What happens when a part lies, is slow, is empty, or drifts?

Every part of an agent's path, crossed with the four ways a part can fail. Each failure ran twice through the same code: once with its check, once without. Pick a square to see both runs.

T-1042"I was charged twice for order O-553. Please refund the duplicate $84 charge."

Real: the LangGraph control loop, the checks, the tool gateway, the release gate, the monitor and the tests that produced these results. Simulated: the model is scripted, faults are injected, tickets are synthetic, and time and cost are computed, so each failure reproduces exactly. The model is treated as one more part that can fail.
