How a question flows

Six steps from sign-in to a cited answer.

Figures are computed in code with provenance. "Not visible to your role" and "no confident answer" are real answers, never guesses.

01Sign in

Teams, the landing zone or the web console establishes who is asking through Entra ID.

02Resolve scope

Compass maps the person to their F&O user: roles, default legal entity, store context. Admin profiles can override.

03Plan

The model picks tools under a schema; verified exemplars of similar questions guide the plan.

04Read live

Read-only OData calls to F&O, scoped to the company; knowledge retrieval over the business's own SOPs for the how-to.

05Compose honestly

Figures are computed in code; the answer names the company, cites sources and states confidence, or declines and logs a gap.

06Record

An episode (tools, checks, latency) is written for evaluation. The nightly battery and the judge read the same evidence.

Access & security

Read-only by construction. Scoped to the person, every time.

No write path exists

The Dynamics client has no write method. Write, form and action tools are never exposed and are refused by name, proven every night by the adversarial cases.

Role ∩ pack

Effective access is always the person's own F&O role intersected with the tool pack. A pack can never widen what a role allows. Finance views stay behind a deny-list.

Fail-closed doors

The landing-zone surface validates signature, tenant, audience, expiry and scope; refuses app-only tokens; accepts only the landing zone's origin; refuses anyone it cannot place as an F&O user.

Zero Trust applied

Verify every request (Entra sign-in or validated bearer, per-client API keys). Least privilege. Assume breach: external content is treated as untrusted input, never as instructions.

OWASP LLM & Agentic Top 10

A written assessment and twelve permanent adversarial cases: injection, disclosure, authority-framed writes, role escalation, PII probes, tool misuse. They run every night.

Supply chain & secrets

Pinned dependencies, dependency audit, an SBOM per build, secret scanning over history. No secrets in the repository; runtime settings live in App Service.

Evaluation harness

How well it is tested.

Evaluation-first: the battery is written before changes, gates every release, and re-runs against production every night.

Seven layers of evidence

  • Trace spineEvery answer leaves an episode: tools, retrieval, checks, latency. 3,738 recorded.
  • Release battery88 exact pass/fail cases: order tracker 28, sales 28, retail 20, adversarial 12. Nothing ships without a green run.
  • Independent judgeGrades groundedness, intent, tool accuracy, task adherence and completeness against the evidence the tools returned. Calibrated at 95% agreement with human review on a 20-case set.
  • Nightly canaryFull judged battery against production at 03:00 AEST, regression analysis against comparable baselines, a Teams card, and a red auto-files a diagnosed GitHub issue.
  • Learning loopEpisodes that pass both layers become gold exemplars retrieved as precedents at planning time. 44 verified; inspectable and deletable; no retraining.
  • Business regressionThe client's original validation workbooks re-run in production and scored with evidence: 46 / 46.
  • Unit tests24 offline tests for token validation, identity, run summaries and router accept/refuse paths, in CI on every commit.

Red nights, honestly

32 nights since 3 September: 25 green, 6 red, 1 running. Functional packs 76 / 76 green every night.

Five of the six reds were one adversarial wording case: the agent refused a write correctly, then offered to fetch. The fence held every time; the first occurrence found a real defect, fixed in v3.6.2 with a tightened no-overpromise rule. One red was a harness timeout, fixed with retry-on-exception and comparable baselines.

Production hardening

The platform explains itself.

Fourteen releases in fourteen weeks: each one gated, each one reversible in a single command, and every failure files its own report.

Compass is operated as a service with a version it can report, a known-good state it can return to, and a nightly check that is harder on it than its users are. Observability is end to end: an answer's episode records the tools called, what retrieval returned, which checks ran and how long each took, so a wrong answer is traced to the step that produced it rather than to the model in general. Dependencies, lint rules and the judge's calibration set are pinned, so a regression is a change someone made, not drift nobody can find.

Releases

  • Rollback bookmark: a reproducible known-good deploy zip and tag; stepping back is one command
  • Release gate: the on-demand canary must be green (v3.7.0: 88/88, judge 82/85)
  • Zero-downtime versioned deploys; the health endpoint reports the live version for warm-poll verification
  • SemVer tags v1.0 → v3.7.0; Conventional Commits

CI on every commit

  • Ruff (pinned) and 24 offline unit tests
  • Dependency audit and an SBOM per build
  • Secret scan over the whole history
  • Self-diagnosing failures: a red night files a GitHub issue with the failing cases and run link, proven 15 and 30 Sep

Controls and kill switches

  • Per-client MCP keys with rate limits
  • The landing-zone surface switches off in one setting
  • Content-boundary rule on by default
  • Honest retries: a failed case is retried once and the first answer is kept, so a flaky wording cannot hide
  • Least-privilege F&O application user over the 39 entities, recipe published

Decisions on record

  • ADR 0001–0006: baseline conformance, packaged agents, portable battery, trace spine and judge, canary gate, landing-zone surface
  • Factory ADR 0115 for the externally hosted agent pattern
  • Playbooks, a spec per packaged agent, security documentation
  • Evidence workbook for the 28/28 acceptance
Governance, safety & guardrails

Lighter where the blast radius is small, heavier where it matters, adversarial every night.

Compass cannot write to the ERP, so its heaviest controls are on who may see what, on honesty about confidence, and on proving every night that the fence still holds.

Humans in the loop, deliberately placed

No person approves a read, because a read is reversible and the scoping is enforced in code. Humans sit where judgement matters: a 20-case calibration set anchors the judge to human review; an editor's approval can promote an episode to a gold exemplar, and every exemplar is inspectable and deletable; every red night is read by a person before the fix ships; business sign-off closes each packaged agent.

Failure modes, designed for

  • Hallucination — figures computed in code with provenance; judge scores groundedness against what the tools returned
  • Prompt injection — twelve permanent adversarial cases: injection, disclosure, authority-framed writes, role escalation, PII probes, tool misuse
  • Out-of-distribution questions — "no confident answer" is a real answer and files a knowledge gap
  • Over-reliance — every answer names its sources and confidence; "not visible to your role" is said plainly

Compliance and transparency

  • Models and retrieval in-region (australiaeast); data stays in the tenant
  • Traces hold statistics, never business content
  • Per-person scoping: roles, legal entity and store follow the signed-in person through every door
  • OWASP Top 10 for LLM and Agentic Applications: written assessment, tests nightly
  • Red nights published honestly: 6 of 32, each one explained
