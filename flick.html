The problem

Consumption invoices are hard for a reason.

Reconciling a consumption-based supplier invoice is evidence work, not spreadsheet work. Each line item is a claim: you consumed this much, at this rate, under this clause, during this window. Closing the line means confirming the reading against a meter, the rate against a contract amendment, the window against the billing calendar and the total against a purchase order.

Done manually, one invoice takes 30 to 90 minutes of analyst time. The failure modes are quiet and expensive: tariff amendments not carried into billing, meter reads missing from the market feed, misapplied network charges, duplicate charges across cycles. Bad reconciliations either pay money the business does not owe or damage the supplier relationship through over-eager disputes.

The manual process also compounds. Every analyst re-learns the same patterns, dispute-rate trends never roll up, and institutional memory sits in inboxes. The platform closes that gap by making every decision a datum: what evidence supported it, what variance was tolerated, what the outcome was.

How it works

Nine steps between an invoice and a posted entry.

The system walks the same steps a human analyst would, but explicitly, in typed state, with citations at every hop.

01Trigger

A user asks the chat bot to reconcile an invoice, or an inbound invoice reaches the ingestion queue by email or API.

02Parse

Parser Agent extracts structured line items from PDF, CSV or EDI with the raw source span for every field.

03Retrieve

Contract, purchase-order and consumption stores are queried over MCP; evidence is attached to shared state with stable identifiers.

04Match

Matcher Agent correlates each line against clause, PO and consumption record, surfacing a ranked candidate list when ambiguous.

05Detect anomalies

Typed checks for tariff drift, missing meter reads, clause mismatch, duplicates, unit-of-measure errors, out-of-window billing.

06Reconcile

Reconciler computes net variance per line and a confidence tier (green, amber, red) calibrated on six months of history.

07Critique

Critic Agent re-reads the set adversarially, on a different LLM vendor. Default position: disagreement.

08Compose

Reporter writes the summary: variance table, plain-English narrative, citations and a recommended action. Teams-native Adaptive Cards.

09Act

Green posts to the ledger. Amber routes to an analyst queue. Red raises a dispute draft held for human release. Every action idempotent and audit-logged.

MCP integration

Systems of record behind a stable, typed boundary.

Each enterprise system is fronted by one MCP server with a small typed surface, four to eight tools, mapped to that system's bounded context. The model sees a stable schema; the server owns the source system's quirks.

Scoped, not sprawling

Each agent sees only the servers its job needs: Parser sees none, Matcher sees contracts and purchase, Reconciler sees meter and ledger. Tool surfaces are audited for capability bloat before every release, because every unused tool is routing noise, attack surface and tokens.

Idempotent and versioned

Every write carries an idempotency key derived from the reconciliation run identifier, so a re-drive or a double click is a no-op, never a duplicate. A new tool version is a schema change the model can see; old versions keep serving until every caller has moved.

Identity at every endpoint

Agents reach servers via Managed Identity; each server holds its own least-privilege service account for the system behind it. Every call carries a correlation ID into Application Insights, so a failure three hops downstream is traced back to its cause.

Agents

One job each, one clean handoff between.

The contract: no agent may emit a claim it cannot support with a cited chunk retrieved this run. No agent may edit another agent's citations. Every mutating action is idempotent, versioned and reversible.

Managerthe supervisortrigger + invoice → ReconciliationRun

Plans the agent chain, dispatches each stage, tracks state through a durable checkpoint, owns token budgets per run, per agent, per model.

Parserreads every invoicePDF · CSV · EDI → normalised line items

Preserves page and paragraph anchors for every field; handles supplier quirks; returns per-field confidence. F1 0.94 across 40+ formats.

Matchercorrelates lines to evidenceline + retrieval hits → ranked candidates

Emits a ranked list, not a hard pick, so downstream tiers can factor in ambiguity. Precision@1 0.91, recall@3 0.98.

Anomaly Detectorflags variancesmatched line + evidence → typed variances

Rules engine plus statistical classifier for tail cases. False-positive rate 3.1% at 95% recall.

Reconcilercomputes tier and confidencematched line + anomalies → tier · action

Composes match strength, severity and historical calibration into green / amber / red. Brier 0.06, ECE 0.02.

Reportercomposes the narrativereconciled set → narrative · card · citations

Every factual claim carries a citation. Teams Adaptive Cards natively; Markdown elsewhere.

Criticadversarial gatecandidate → approve · route to review

Runs on a different LLM vendor. Looks for unsupported claims, weak citations, tier inflation. True-reject 0.88, false-reject 0.04.

Evaluation harness

Quality is measured, not asserted.

Every prompt change, model bump and agent revision runs against a golden set before it reaches production traffic.

The golden dataset

Two hundred historical reconciliations hand-labelled by finance analysts across twelve months of production data. Weighted toward the tail: 40% straightforward, 40% amber-tier variances, 20% red-tier disputes. Each item carries ground-truth tier, variance category and a short human rationale.

How a change reaches production

  • Unit testsDeterministic checks on parsers, coercers, schema repairs, MCP contracts. Blocks the merge on any red.
  • Golden-set regressionRuns overnight against all 200 items. Alarms when any per-agent metric drops more than 2 points week-on-week.
  • Canary slot5% of production traffic for 24 hours, metrics paired against baseline.
  • Human review sampleA rolling 10% of production runs is human-reviewed; corrections feed the golden set monthly.
  • Ramp5% → 25% → 50% → 100% over four hours, automatic rollback on any regression beyond the change budget.

Production hardening

Hardened for the tail, not the demo.

The unhappy paths decide whether a system is trusted with money. Every control below is named after the failure it prevents, and each one was walked before the pilot took live traffic.

The platform is run as a production service, not as a model with a chat window. It has latency and error-rate objectives per stage, a health check per agent, and breakers that degrade rather than fail: a tripped MCP server returns a cached read or defers the run, it never stalls the queue. Binary-correctness work, variance arithmetic, tier thresholds and ledger postings, is plain code. Model weights, prompt versions, tool definitions and runtime configuration are pinned per run, so any reconciliation can be replayed exactly.

Reliability

  • Circuit breakers on every external tool call; open breaker → cached read or deferral
  • Retries with exponential backoff and shared jitter on 429 / 502 / 503 / 504
  • Idempotency keys on every mutating call; a re-drive is a no-op
  • Timeouts at every layer, decreasing client → tool; slow tools raise specific errors, not stalls
  • Two-provider LLM strategy; fallback on credit exhaustion, quota block or auth revocation, logged per event
  • Model version pinned per run; structured error taxonomy on every failure

Security & identity

  • Managed Identity between every layer; zero long-lived secrets; Key Vault 30-day rotation
  • Conditional Access; MFA for mutating actions
  • Content Safety on every prompt and response: jailbreaks, injection in invoice text, PII exfiltration
  • PII redaction at ingress: names, phones, tax identifiers scrubbed before embedding
  • Least-privilege MCP tokens; each server its own service account
  • Prompt-injection defence: untrusted text enters tagged as data, never as instruction

Cost & governance

  • Per-user daily cost caps
  • Per-run budget accounting: input, output, cache reads and writes, per agent and model; the Manager halts a run that exceeds its budget
  • Prompt versioning in an immutable store; rollback is one commit
  • Approval gates above threshold; no action executes without the gate
  • Data residency: at rest and in transit, the customer's home region
  • Retention: 7 years financial, 90 days run bundles; GDPR erasure path

Deployment & DR

  • Bicep infrastructure as code; dev → prod parity
  • Blue/green slots; ramp over 30 minutes with auto-rollback on error-rate regression
  • Cross-region replication; MCP servers active-active
  • RTO 4 h · RPO 15 min; failover exercised quarterly
  • Nightly restore tests against a scratch environment
  • Network egress restricted; container-based execution
Governance, safety & guardrails

Humans where it is irreversible

Review is an architectural decision, not a checkbox. Green-tier OpEx posts automatically because it is reversible and low-value. Amber waits in an analyst queue with the evidence attached. Red, disputes and reversals need a named person's approval in a Teams card. Reviewers see the variance table and citations, not a transcript, so routine approvals take seconds and real decisions get attention.

Failure modes, designed for

  • Hallucination — the citation contract plus the Critic; true-reject 0.88
  • Prompt injection via invoice text — Content Safety and data tagging; the parser never executes instructions
  • Out-of-distribution input — unfamiliar formats fall to amber, not to a guess; false-positive rate 3.1% at 95% recall
  • Over-reliance — a rolling 10% of production runs is human-reviewed and corrections feed the golden set monthly

Compliance and transparency

  • Data stays in the customer's region at rest and in transit
  • Financial records retained 7 years; run bundles 90 days; GDPR erasure path
  • Purview for lineage, PII discovery and audit export
  • Every decision is a datum: evidence used, variance tolerated, outcome recorded
  • Per-supplier dispute-rate trends are reported, so uneven outcomes are visible rather than buried in inboxes
